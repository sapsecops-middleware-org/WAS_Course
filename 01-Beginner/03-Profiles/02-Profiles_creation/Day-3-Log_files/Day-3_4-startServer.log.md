# WebSphere `startServer.log` — Complete Beginner's Guide

## Overview

`startServer.log` is a short, startup-only log file generated by IBM WebSphere Application Server every time a server process is started (via `startServer.sh`, `startManager.sh`, etc.).

Think of it as a **birth report card** for the server: it records only whether the startup succeeded or failed — not day-to-day runtime activity.

> [!NOTE]
> This is **not** the full server log. For runtime activity, use `SystemOut.log` instead.

---

## Key Concepts

| Term | Analogy | Meaning |
|---|---|---|
| WebSphere installation | The office building | The full product install |
| Profile | A room in the building | A workspace with its own configuration |
| Server | A worker in the room | The process that actually runs your apps |
| `startServer.log` | The worker's diary entry | Startup-only report: success or failure |

---

## Log Location

The log lives **with the server it started**, inside that server's own `logs` folder.

| What you started | Log location |
|---|---|
| Application server (`server1`) | `profiles/AppSrv01/logs/server1/startServer.log` |
| Deployment Manager (`dmgr`) | `profiles/Dmgr01/logs/dmgr/startServer.log` |

> [!TIP]
> **Memory trick:** The log lives with the server it started. `server1`'s log sits in `server1`'s folder; `dmgr`'s log sits in `dmgr`'s folder.

---

## How to Read It

```bash
# Correct — read the LOG file
cat /opt/IBM/WebSphere/AppServer/profiles/AppSrv01/logs/server1/startServer.log

# Watch it live while the server starts
tail -f /opt/IBM/WebSphere/AppServer/profiles/AppSrv01/logs/server1/startServer.log

# See the last 20 lines
tail -20 /opt/IBM/WebSphere/AppServer/profiles/AppSrv01/logs/server1/startServer.log
```

> [!WARNING]
> **Common mistake:** Do NOT open `startServer.sh` — that is the startup *script*, not the log.
>
> - `.sh` = the button you press
> - `.log` = the report you read

## Understanding Message Codes

Every line starts with a code such as `ADMU0116I`, broken down as:

| Part | Meaning |
|---|---|
| `ADMU` | **ADmin Utility** — message from the startup tool |
| 4 digits | Unique message number |
| Last letter | Severity level |

### Severity Letters

| Letter | Meaning | Panic level |
|---|---|---|
| `I` | Information | 🙂 Normal |
| `W` | Warning | 😐 Look into it |
| `E` | Error | 😰 Something broke |
| `A` | Audit | 🙂 Tracking action |

> [!TIP]
> **Memory trick:** **I** = Info, **W** = Worry a little, **E** = Emergency.

---

## What Success Looks Like

```text
ADMU0116I: Tool information is being logged in file:
ADMU0128I: Starting tool with the AppSrv01 profile
ADMU3000I: Server server1 open for e-business; process id is 12345
```

Line-by-line translation:

- `ADMU0116I` → "Here's where the detailed log lives."
- `ADMU0128I` → "I'm using the AppSrv01 profile (this room's settings)."
- `ADMU3000I` → "The server is UP and accepting work. Its process ID is 12345."

### The Golden Line

```text
ADMU3000I: Server server1 open for e-business
```

If you see this, **startup succeeded**. Done.

---

## What Failure Looks Like

```text
ADMU0111E: Program exiting with error: ...
```

- `ADMU0111E` → The `E` means **Error**. The startup tool gave up.
- The text after the colon tells you **why**.

### Example: Port Already in Use

```text
ADMU0111E: Program exiting with error:
java.lang.Exception: ADMU0111E: Port 9080 is already in use
```

**Translation:** "Another program is sitting on the chair (port 9080) this server wanted."

---

## Troubleshooting: Startup Hangs

**Scenario:** You run `startServer.sh`. It hangs for 5 minutes. Nothing happens.

1. Open `startServer.log`.
2. Find the last line it wrote before getting stuck.
3. That last line = exactly where it stopped.

> [!TIP]
> **Analogy:** A road trip with checkpoints. If the car never arrives, the last checkpoint stamp tells you where it broke down.

---

## Common Problems This Log Reveals

| Symptom in log | What it usually means |
|---|---|
| Server hangs, no `ADMU3000I` | Still starting, or stuck (check `SystemOut.log` for deeper cause) |
| `ADMU0111E` + port in use | Another server/process owns the port |
| `ADMU0111E` + file not found | Broken profile or missing configuration |
| `ADMU3027E` | Conflict — server instance already running |
| Startup too slow | Often JVM memory settings or database connections |

---

## Golden Rules (Quick Recap)

- ✅ `startServer.log` = **startup only** — a short report card.
- ✅ Found in the **server's own logs folder**.
- ✅ Read the **last letter** of each code: `I` = fine, `W` = warning, `E` = error.
- ✅ `ADMU3000I` = **success**. Commit it to memory.
- ✅ `ADMU0111E` = **failure**. Read the message after it.
- ✅ When startup hangs, this log tells you **where it got stuck**.
- ✅ `.sh` runs, `.log` reports — don't mix them up.
